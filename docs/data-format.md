# 카드·부품 데이터 형식

다른 AI에게 부품 설계를 부탁하면 이 형식의 JSON을 받을 수 있습니다. 앱에서 **내 기체 → 파일 가져오기**로 열면 카드와 기체가 그대로 들어옵니다.
가져오기 파일의 `parts`는 무시됩니다. 읽히는 것은 `custom`(내 카드)과 `ships`(저장한 기체)뿐입니다.
완성된 예시는 `examples/example-cards.json`에 있습니다.

## 파일 전체

```json
{
  "app": "holo-assembly",
  "v": 3,
  "custom": [ 카드, ... ],
  "ships":  [ { "name": "기체 이름", "t": 1794969676720, "parts": [ 부품, ... ] } ],
  "parts":  []
}
```
- `ships[].parts`의 순서는 **아래에서 위로**입니다. 0번이 맨 아래(보통 엔진부)입니다.
- `t`는 저장 시각(밀리초)입니다. 아무 숫자나 넣어도 됩니다.

## 카드

```json
{ "id": "ai_tank_01", "cat": "st", "custom": true, "name": "카드 이름", "kind": "tank",
  "desc": "카드에 보일 한 줄 설명", "part": { 부품 } }
```
- `id`는 겹치지 않는 문자열이어야 합니다. 이미 있는 id는 가져올 때 건너뜁니다.
- `kind`는 `part.role`과 같은 값입니다.

## 부품

| 필드 | 값 | 설명 |
|---|---|---|
| `name` | 문자열 | 부품 이름 |
| `role` | `tank` `engbay` `inter` `hotring` `shell` `capsule` | 역할. 연료는 tank에만, 엔진과 착륙 다리는 engbay에만 붙음 |
| `shape.prof` | `line` `ogive` `dome` `bulb` `boat` | 원통·원뿔·테이퍼는 모두 `line`(d0, d1으로 구분). 오자이브 노즈, 돔, 페어링(볼록), 스커트 |
| `shape.h` | 0.3–80 | 길이 (m) |
| `shape.d0` | 0.3–15 | 아래 지름 (m) |
| `shape.d1` | 0–15 | 위 지름(노즈 끝이면 0) (m) |
| `shape.dm` | 0.3–18 | 페어링 최대 지름 (m), `bulb`에서만 사용 |
| `shape.sp` | 0.3–0.85 | 페어링이 닫히기 시작하는 높이 비율, `bulb`에서만 사용 |
| `shape.k` | 1–4 | 오자이브 뾰족함, `ogive`에서만 사용 |
| `mat` | 객체 | 아래 재질 표의 키 하나 + 성질 값 전부 |
| `build` | `mono` `stringer` `iso` `honey` | 단일 외피, 스트링거 보강, 아이소그리드, 허니콤 샌드위치 |
| `t` | 0.5–40 | 벽 두께 (mm) |
| `meop` | 0–20 | 운용 압력 (bar). 탱크 3–6, 그 밖의 부품 0.3 정도 |
| `tps` | `hex` `pica` `cork` `blanket` `foam` `mli` `rcc` 또는 `null` | 단열재 |
| `tpsT` | 1–150 | 단열재 두께 (mm) |
| `fuel` | `methalox` `kerolox` `hydrolox` `hyper` `solid` 또는 `null` | 탱크 연료 |
| `engines` | `raptor` `raptorvac` `merlin` `mvac` `rs25` `rl10` `be4` `srb` 의 배열 | 엔진부에 다는 엔진 (최대 40개) |
| `att` | `gridfin` `legs` `flaps` `fins` 의 배열 | 부착물 |
| `tests` | `{}` | 비워 두면 됨 (앱에서 시험하면 채워짐) |
